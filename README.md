# be10X Success Stories

Production-ready success stories directory and admin dashboard for be10X learner achievements. Data is sourced from the **Testimonial YT Audit** workbook (three sheets: Vishesh, Saurabh, Vivek).

## Stack

- **Frontend:** React 19, [TanStack Start](https://tanstack.com/start/latest) (SSR + file routes), TanStack Router, TanStack Query, TypeScript, Vite, Tailwind CSS v4, Lucide icons
- **Fonts:** Space Grotesk (headings), DM Sans (body)
- **Brand colors:** `#030200` (black), `#106CF7` (blue accents)
- **Logo:** `public/be10x-logo.svg` (sourced from [be10x.com](https://be10x.com/wp-content/uploads/2026/09/Layer_1.svg))
- **Local preview API:** Express + SQLite + HTTP-only JWT admin sessions
- **Production target:** Supabase (Postgres, Auth, Storage) — schema in `supabase/migrations/`

## Quick start (local preview mode)

This mode uses a real SQLite database and authenticated admin API. It does **not** use hardcoded frontend passwords.

```bash
npm install
cp .env.example .env   # set ADMIN_EMAIL, ADMIN_PASSWORD, JWT_SECRET
npm run import:data      # imports sheets + extracts embedded photos (see below)
npm run dev:all          # API :4318 + TanStack Start (Vite) :4317
```

### Photos from Excel / Google Sheets

Learner photos in the Google Sheet are **in-cell images**, not URLs. A plain `.xlsx` upload often strips them.

`npm run import:data` will:

1. Download the latest `uploads/Testimonial_YT_Audit_google.xlsx` from Google Sheets (`GOOGLE_SHEET_ID` in `.env`). Without `--fetch-google`, `import_excel.py` picks whichever local `uploads/*.xlsx` has the most embedded images.
2. Extract images into `data/uploads/learners/` and set `photoUrl` to `/uploads/learners/{id}.jpg|png`.
3. Sync `photo_url` into the local SQLite database.

**Manual photos:** In `/admin/dashboard`, select a learner → **Upload image file** or paste a **Photo URL**, then Save. Uploads are written to disk, SQLite, and the JSON exports immediately.

**Automated sync from Google Sheets:** With the API running (`npm run dev:api` or `npm run dev:all`), run:

```bash
npm run import:watch
```

This re-downloads the sheet export every `IMPORT_WATCH_INTERVAL_SEC` seconds (default 300). When the workbook hash changes, it re-imports rows, extracts photos, and runs `sync_sqlite_from_json.py` so the live API serves new `photo_url` values without a restart. The public site polls `/api/stories/version` and refreshes story data (and photo cache keys) in open browsers.

One-off import (downloads the latest Google export, then syncs SQLite):

```bash
npm run import:data
```

To import from a local `.xlsx` without re-downloading:

```bash
python3 scripts/import_excel.py --workbook uploads/your-copy.xlsx && python3 scripts/sync_sqlite_from_json.py
```

Open [http://127.0.0.1:4317](http://127.0.0.1:4317).

**Admin (local preview):** [http://127.0.0.1:4317/admin/sign-in](http://127.0.0.1:4317/admin/sign-in)  
After sign-in: [http://127.0.0.1:4317/admin/manage-stories](http://127.0.0.1:4317/admin/manage-stories)

Use `ADMIN_EMAIL` and `ADMIN_PASSWORD` from your `.env` (see `.env.example` for local defaults).

On first API start, SQLite seeds from `data/private-stories.json` (generated by import; gitignored).

## Data import

```bash
python3 scripts/import_excel.py
```

Outputs:

| File | Purpose |
|------|---------|
| `data/private-stories.json` | Full records incl. email (gitignored) |
| `data/public-stories.json` | No emails — safe reference export |
| `reports/import-meta.json` | Row counts per sheet |
| `reports/duplicate-report.json` | Potential duplicate groups (email, LinkedIn, name) |

Re-import after workbook updates (`npm run import:data` or `npm run import:watch`). SQLite is upserted from JSON on each import; no API restart required.

## Privacy

- Emails are stored only in the private dataset / admin API.
- Public routes and `public-stories.json` never include email unless `emailPublishAllowed` is explicitly set in admin.

## Production (Supabase)

1. Create a Supabase project.
2. Run `supabase/migrations/20260324120000_success_stories.sql`.
3. Create storage bucket `success-story-photos` with admin-only write policies.
4. Set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` in the frontend; use service role for a secure import job or Edge Function.
5. Map admin users via Supabase Auth and JWT `role: admin` for RLS policies.
6. Deploy the Vite build to your CDN/host; point API traffic to Supabase client reads (replace local Express routes when wired).

The codebase ships with **local preview** fully working; Supabase wiring is documented in migration + `.env.example` without committed secrets.

## Handoff for be10X tech team

1. Place the latest `Testimonial YT Audit.xlsx` in `uploads/` and run `npm run import:data`.
2. Review `reports/duplicate-report.json` before merging ambiguous name matches manually in admin.
3. Configure production env vars (never commit `.env`).
4. Publish/unpublish and feature stories in `/admin/dashboard`.
5. Run `npm run build` and deploy `dist/` plus your chosen backend (Supabase recommended).
